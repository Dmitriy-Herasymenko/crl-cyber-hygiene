# Кібергігієна для медичного персоналу

Навчальна сторінка з інструктажу «Основи кібербезпеки та захисту персональних
даних пацієнтів»: 4 короткі курси (паролі, фішинг, носії, блокування екрана)
з детальним поясненням і міні-питанням по кожному, фінальний тест по всіх
темах та адмін-панель з результатами всього персоналу.

## Стек

- **Next.js (App Router) + TypeScript + Tailwind** — фронтенд і API-роути
- **Neon (Postgres) + Drizzle ORM** — зберігання результатів і прогресу курсів
- Проста пароль-авторизація адміна (HttpOnly cookie, підписана HMAC)

## Локальний запуск

1. Створіть безкоштовну БД на [neon.tech](https://neon.tech) і скопіюйте
   connection string.
2. Скопіюйте `.env.example` у `.env` і заповніть:
   ```
   DATABASE_URL=...       # з кабінету Neon
   ADMIN_PASSWORD=...     # пароль для входу в /admin
   SESSION_SECRET=...     # будь-який довгий випадковий рядок
   ```
3. Встановіть залежності та застосуйте схему БД:
   ```bash
   npm install
   npm run db:push
   ```
4. Запустіть дев-сервер:
   ```bash
   npm run dev
   ```
   - Головна сторінка: http://localhost:3000
   - Адмін-панель: http://localhost:3000/admin

## Структура

- `src/lib/quiz-data.ts` — питання фінального тесту (5 сценаріїв: фішинг,
  блокування екрана, знімні носії, спільні паролі, підозріла активність).
- `src/lib/courses-data.ts` — 4 курси (паролі, фішинг, носії, блокування
  екрана) з детальним поясненням і посиланням на відповідне питання з
  `quiz-data.ts` для міні-тесту по курсу.
- `src/lib/departments-data.ts` — список відділень для випадаючого списку у
  формі ПІБ.
- `src/db/schema.ts` — таблиці `attempts` (завершені спроби фінального
  тесту), `attempt_answers` (відповіді по кожному питанню) та
  `course_progress` (які курси хто вже пройшов, за ПІБ).
- `src/app/admin/page.tsx` + `src/components/AdminTable.tsx` — захищена
  сторінка з таблицею результатів, фільтром по відділенню, пошуком по ПІБ та
  експортом у CSV.

## Ідентифікація персоналу (без окремих акаунтів)

Сторінка розрахована на спільний комп'ютер у відділенні. Людина вводить ПІБ і
відділення один раз — ці дані зберігаються в браузері (`localStorage`), щоб
оновлення сторінки не скидало на початок. Весь прогрес (пройдені курси,
результат тесту) підтягується з бази даних за ПІБ, а не з браузера, тому
дані різних людей не змішуються. Перед тим як передати комп'ютер колезі,
потрібно натиснути **«Вийти»** у шапці сторінки.

## Деплой на Vercel

1. Запуште репозиторій на GitHub і імпортуйте у Vercel.
2. У Vercel додайте інтеграцію **Neon** (Storage → Neon) — вона сама підставить
   `DATABASE_URL`, або додайте змінні оточення вручну (`DATABASE_URL`,
   `ADMIN_PASSWORD`, `SESSION_SECRET`) у Project Settings → Environment
   Variables.
3. Перед першим деплоєм застосуйте схему до продакшн-БД:
   ```bash
   DATABASE_URL="<production-url>" npm run db:push
   ```
4. Задеплойте — Vercel автоматично збере Next.js-застосунок.

## Нотатки з безпеки

- Пароль адміна та секрет сесії зберігаються тільки в змінних оточення, не в
  коді.
- Сесія адміна — HttpOnly, Secure (у продакшені) cookie з HMAC-підписом і
  часом життя 12 годин.
- ПІБ персоналу — вільний текст, відділення обирається зі списку в
  `departments-data.ts` (з опцією «Інше» для ручного вводу).
